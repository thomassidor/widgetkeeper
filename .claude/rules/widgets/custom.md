# Widget Builder (`custom`)

- **The user's design (2026-11-20, two mock-ups, the second approved; `temp/widget-builder-mockup.html/.png`, on the branch `mockup-widget-builder` until it's built):** the user's own widget from parts, web dashboards first. A **design** is built once on the web dashboards' builder page and placed on any web dashboard (the widget's `design` setting); a change shows on every copy. The name is the user's pick (over Custom Widget and My Widgets). 1.4.0.
- **Web only for now**, like Dashboard Shortcuts: `deprecated: true`, so Homey's Add widget leaves it out; on a Homey dashboard (an instance not `web-…`) it says `custom.webOnly` without asking the app. It's its own iframe widget so native dashboards can come later (a design picked from the autocomplete). Not a Smart Stack page.
- **The model** (`lib/customDesigns.ts`, no Homey): `Design {id, name, updatedAt, parts}`; a `Part {id, kind, name, at, color, icon, tile, rules, flow, reset, …}` with only its kind's fields (`readPart()`: `slot` for the device kinds (`SLOT_KINDS`), `variable` for stepper/choice/variable without a slot, `flowId` for a button, `text`/`size`/`align` for text, `text`/`units` for a Flow value, `min`/`max`/`step`, `choices` (≤ 6, unique values), `span`/`show` for charts, `mode`/`background`/`parts` for a container). Read leniently (`readDesign()`): unknown kinds and broken rules left out, repeated ids renewed, containers one level deep, ≤ 80 parts in all, ≤ 50 designs, reserved ids (`__proto__` …) refused.
  - **Places:** top level, cells of the 4-column grid (64 px rows, 8 px gaps; `x`, `y` from 0); in a container on its **fine grid** (`mode: 'grid'`: 12 columns, 8 px rows, 6 px column gap) or **free-form** (`mode: 'free'`: per cent of its inner box, one decimal, so it scales with the widget's width).
  - **Kinds** (the user's picks: the first set plus six of ten proposed): value, chart (Mini chart), gauge, level (Level bar), status, flowvalue (only Flows fill it, as Flow Tiles' tiles), switch, button, slider, stepper, choice, variable, container, text, icon. Later (proposed, not picked for 1.4.0): Camera, Now playing, Clock, Weather now; also Image, Countdown, Price strip, Lock, Light colour, Room summary.
  - **Rules** (`{op: above|below|is|isNot, value, look: colour|'hide'}`, ≤ 6; `look`, not `then`: an object with `then` is a thenable, Biome's `noThenProperty`): the first that holds wins. `ruleHolds()` compares numbers for above/below (a boolean as 1/0, a decimal comma read), else text without case, `on/yes/true/open` and `off/no/false/closed` as a boolean's; the widget's copy `customRuleHolds` is checked equal over a grid of values.
  - **Colour:** a part's own colour only accents it (its icon, toggle, bar, line, dot; `wb-has-color`); a rule's or a Flow's colour tints the whole tile 22 % (Vivid: solid with `--wk-on`; `wb-colored`), so a tinted tile means something to notice. A switch or a yes/no variable that's on tints in its colour, as Quick Actions'.
- **Flow support, opt-in** (the user's ask: "not automatically for everything, but where the user decides"): `part.flow` lists what a Flow may change (`text`, `color`, `hidden`, `icon`, `value`; a Flow value part takes `value` always), and `reset` when it goes back (`never`, `hour`, `midnight` local). The cards' `part` argument lists only parts open to that change, as `Design · Part` (`partLabel()`), id `<designId>/<partId>`; one not open throws. Values are kept in the app setting `customFlowValues` `{[design]: {[part]: {text?, value?, units?, color?, icon?, hidden?, at}}}` (`DebouncedSetting`, 2 s, flushed in `stop()`, the first `onUninit()` group), sent as realtime `custom:flow {design, part, values | null}`, and served in `/state`'s `flow` with `expires`; a timer drops the next to expire and sends `null`. Saving a design drops what its parts no longer allow.
  - Cards: `custom_set_text`, `custom_set_value` (`value` a text arg, a number if it reads as one, optional `units`), `custom_set_color` (Device Values' colour list), `custom_set_custom_color` (`parseCustomColor()`), `custom_set_icon` (Flow Buttons' icon list), `custom_show` (`shown`: show/hide), `custom_reset` (everything Flows set); the condition `custom_is_shown` (hidden by a Flow only: the rules weigh values only the widget has); the triggers `custom_tapped` (a button without a Flow; tokens part, design, dashboard) and `custom_choice` (after a choice was set; tokens choice, value, index). Titles name the widget, *Widget Builder*.
- **The service** (`lib/CustomWidgetService.ts`, `app.custom`): the designs in the app setting `customDesigns` (an array, the library's order; written at once on a save), `save()` (a new one gets an 8-character id; realtime `custom:design {id}`), `remove()`, `duplicate()` (new ids throughout, `<name> (copy)`), `reorder()`, `designItems()` (the widget's Design autocomplete, `custom.partCount`). **`getState(id)`** gathers what a design shows from the services that read it already: `values` by slot (`ValueService.getState()`, so device names, offline, °C/°F as Device Values), `variables` by id, `flows` by id, `histories` by `<span>\n<slot>` (`SparklineService.getState()`), and `flow`; `{missing: true}` for a design that's gone.
  - **A request acts only through its design's own part** (`partFor()`): `setValue()` sets the part's capability (switch: a boolean; slider/stepper: a number clamped to the capability's and the part's range; choice: one of its values, typed to the capability; a temperature shown in °F, and a part range typed in it, converted back to the device's unit), `setVariable()` (through `VariableService.set()`, the personal key), `startFlow()` (`FlowService.trigger()`, the key), `tap()` (a button without a Flow fires the trigger, no key). Routes: `GET /state?design=`, `POST /set` (in `DEVICE_WRITES`), `POST /variable` (`variables` key use), `POST /flow` (`flows`), `POST /tap` (neutral).
- **The widget** (`widgets/custom/public/`, prefix `wb-`, transparent): `createCustomWidget(root, {onSet, onButton, preview, …})`, built once per design (`updatedAt`; a slider's drag survives a refresh) and updated in place. Part classes are `wb-k-<kind>` (not `wb-<kind>`: `.wb-icon`/`.wb-text` are inner elements). Quick Actions' native tile (`wb-tile`, in kit.css's tile lists, so the web backdrop's line and the light-mode shadow apply). A big value at 2 rows (10 fine rows, 40 % free) puts the number at 32 bold with the line under it; a one-column value is icon over value, the name as its tooltip. Taps through the kit's `onTap()`, the slider through `wireBar()`, a stepper's burst sent once 700 ms after the last tap (Variables'), hoped-for values for 10 s, a failure shakes the part with `KEY_PROBLEMS`' text or `custom.setFailed`. A text variable is edited with the browser's `prompt()` for now. `preview: true` (the builder page) acts on nothing.
- **Mount:** the instance decides web or not; `/state` on load, every 5 min, on `custom:design` for its design and on device names/temperature unit (`onDeviceNames()`); realtime `values:state`, `variables:state`, `custom:flow`; `takeTileShadow()` from its answer, `wireTileShadow()`, `wireHaptic()`.
- **Dev and renders:** `dev/mock-custom.js` (`mockCustomState(scene)`: living, container, free, rules, controls; the made-up house's devices), `MOUNT.custom`, `SCREENSHOTS.custom` (the living room design), Looks (Light, Vivid, a container on its fine grid, free-form with a Flow's message, rules, the controls). The preview (`wb-dark`/`wb-light`): a design of drawn tiles, one outlined dashed as in the builder, under the logo's sparkle on the brand colour.
- **The builder page** (`settings/dashboard-builder.js`, the page's part `builder`, before `nav`; step 2, 2026-11-20): the front page's **Widget Builder** section after the dashboards (`designsSection()`: a card per design with a sketch of its grid, `New design`), and `#/builder/<id>` (`renderBuilder()`; the route sits after the code-locked `stay` check, so a held tablet can't open it; no side pane). The bar: back, the name (saved on change), a select of the designs, *Saved / Saving… / Not saved*, Undo (50 steps of the whole design, in memory), Duplicate, Delete (`confirmButton()`, `wd-bar-delete`), **Add to dashboard** (a dashboard's first column gets a `custom` widget titled and set to the design) and Done (sends a waiting save first). Left: **Parts** (a search, `matchesWords()`, and the groups Show, Control, Layout as the kit's icons; a tap adds the part at the bottom, or into the selected container or the container of the selected part, with a size per kind) and **Layers** (the tree, ↑ ↓ to reorder: later is drawn on top, ⚡ for parts open to Flows). Middle: the size (300/440 px), Dark/Light and Muted/Vivid, then **the real widget in a same-origin frame** (`srcdoc` loading kit.css, `custom/widget.css`, kit.js, icons.js and `custom/widget.js` from where the page loaded the kit, so the Homey's `../widgets/<id>/` and the dev pages' `../widgets/<id>/public/` both work, plus Homey's `homey.widgets.css` where the page has it): the widget's stylesheet sets `html, body` and can't go on the page. `preview: true`, so nothing acts. An **overlay** of boxes from each part's rect in the frame: a tap selects, a drag moves, the selected one's corner resizes; the pointer is captured on the overlay (the boxes are redrawn as a part moves). On the top grid and a fine grid a move or resize **pushes overlapped parts down** (`makeRoom()`, from where they were when the drag started, so they come back as it goes on); free-form snaps a part's edges and middle to its siblings' and the box's 0/50/100 % within 2 % with pink lines. Right: **Part** (name or text, the value (`chooseValue()` with `/web/values?type=values`, so every readable capability; a choice on an enum or a yes/no fills its choices), or a variable or Flow from `POST /web/designs/pick`, the range, step, span, choices, a container's mode (switching keeps each part's place, cells ↔ per cent) and background colours (`<input type=color>`), and the place as numbers (columns and rows from 1 for the grids, per cent free-form), Remove), **Look** (colour swatches with *Its own*, the colour names from Dashboard Shortcuts' colour setting so no new strings; icon through `pickIcon()`, pictures not taken; in a container, on a tile or on the background), **Rules** (op, value, colour or Hide, ≤ 6) and **Flow** (a switch per change the kind shows, each with the card it adds; *Back to the design*). Every change draws at once and is saved 500 ms later (`PUT /web/designs`, queued on `wd.saving`); the values are read again 400 ms after a change (`POST /web/designs/preview`, the draft's state without saving). Routes: `PUT /web/designs`, `DELETE /web/designs/:id`, `POST /web/designs/:id/copy` (each answering the library), `POST /web/designs/preview`, `POST /web/designs/pick {what: flow | variable, query}`, all `assertWebSession()`; `/web/setup` has `designs`. Strings `web.builder*` (136, all 13 languages). Tested: `test/web-builder.test.ts` (the routes); the page clicked through in Chromium over DevTools on `dev/web-preview.html` (select, resize with the others pushed down, add, Layers, a free-form drag with snapping, the Flow tab, the front page, 390 px), whose mock has the designs, saves and previews (`dev/mock-web-api.js`). Not in a happy-dom test: the frame's widget needs a real browser.
- **The user's review (2026-11-21), and what changed:** the UI says **components**, never parts (the editor, the widget's messages, the Flow cards' titles, hints and argument, the README; the code and stored data keep `part`). The copy was rewritten plainly (the user: "With its line", "Drawn: On a tile / On the background" and "Back to the design: Never" meant nothing to anyone): tabs Settings, Style, Rules, Flows; groups Layout (first), Display, Controls; *Value only / Value and graph*, *Graph period*, *Placement: Snap to grid / Free placement*, *Position and size*, *When the value…* over the rules, *Reset Flow changes: Never / After 1 hour / At midnight*, *Label* with the device's own name as its placeholder, *Automatic* for an empty range. The chosen device value shows as the value picker's row (the device over the value's name and reading, from `/web/values?type=values`, read as the builder opens; *Device not found* rather than the raw id). A **moon/sun** in the bar sets this browser's dark or light (the page's `THEME_STORAGE`, as Settings' Dark or light), the preview with it; the preview's own Dark/Light switch went. **Drag and drop** from the library (`dragToAdd()`: a ghost follows the pointer, the canvas is outlined while over it, the drop goes to the cell under the pointer or into the container under it, the others making room; a tap still adds). **A background per component** (`style`: `tile`, `pill`, `none`; the Style tab's Background; `readPart()` reads the never-released `tile: false` as `none`, text and icons default to none): the pill is fully rounded, and a one-row value, Flow value, switch, status, variable or button lays out in a row (icon, name, then value or switch; `.wb-top` as `display: contents`); the overlay's outline takes the component's radius.
