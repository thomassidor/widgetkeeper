# Widget Builder (`custom`)

- **The user's design (2026-11-20, two mock-ups, the second approved; `temp/widget-builder-mockup.html/.png`, on the branch `mockup-widget-builder` until it's built):** the user's own widget from parts, web dashboards first. A **design** is built once on the web dashboards' builder page and placed on any web dashboard (the widget's `design` setting); a change shows on every copy. The name is the user's pick (over Custom Widget and My Widgets). 1.4.0.
- **Web only for now**, like Dashboard Shortcuts: `deprecated: true`, so Homey's Add widget leaves it out; on a Homey dashboard (an instance not `web-…`) it says `custom.webOnly` without asking the app. It's its own iframe widget so native dashboards can come later (a design picked from the autocomplete). Not a Smart Stack page.
- **The model** (`lib/customDesigns.ts`, no Homey): `Design {id, name, updatedAt, parts}`; a `Part {id, kind, name, at, color, icon, tile, rules, flow, reset, …}` with only its kind's fields (`readPart()`: `slot` for the device kinds (`SLOT_KINDS`), `variable` for stepper/choice/variable without a slot, `flowId` for a button, `text`/`size`/`align` for text, `text`/`units` for a Flow value, `min`/`max`/`step`, `choices` (≤ 6, unique values), `span`/`show` for charts, `mode`/`background`/`parts` for a container). Read leniently (`readDesign()`): unknown kinds and broken rules left out, repeated ids renewed, containers one level deep, ≤ 80 parts in all, ≤ 50 designs, reserved ids (`__proto__` …) refused.
  - **Places:** top level, cells of the 4-column grid (64 px rows, 8 px gaps; `x`, `y` from 0); in a container on its **fine grid** (`mode: 'grid'`: 12 columns, 8 px rows, 6 px column gap) or **free-form** (`mode: 'free'`: per cent of its inner box, one decimal, so it scales with the widget's width).
  - **Kinds** (the user's picks: the first set plus six of ten proposed): value, chart (Mini chart), gauge, level (Level bar), status, flowvalue (only Flows fill it, as Flow Tiles' tiles), switch, button, slider, stepper, choice, variable, container, text, icon; 2026-11-21 shape, calc, time, then state, image, ring, repeat (and the containers' pages), then segments, trend. Later (proposed, not picked for 1.4.0): Camera, Now playing, Clock, Weather now; also Image, Countdown, Price strip, Lock, Light colour, Room summary. Added the same day: shape, calc (Calculated value), time, plus texts with values and rules on other values (*Building blocks* below).
  - **Rules** (`{op: above|below|between|is|isNot, value, to?, look: colour|'hide'}`, ≤ 6; `look`, not `then`: an object with `then` is a thenable, Biome's `noThenProperty`): the first that holds wins. `ruleHolds()` compares numbers for above/below (a boolean as 1/0, a decimal comma read), else text without case, `on/yes/true/open` and `off/no/false/closed` as a boolean's; the widget's copy `customRuleHolds` is checked equal over a grid of values.
  - **Colour:** a part's own colour only accents it (its icon, toggle, bar, line, dot; `wb-has-color`); a rule's or a Flow's colour tints the whole tile 22 % (Vivid: solid with `--wk-on`; `wb-colored`), so a tinted tile means something to notice. A switch or a yes/no variable that's on tints in its colour, as Quick Actions'.
- **Flow support, opt-in** (the user's ask: "not automatically for everything, but where the user decides"): `part.flow` lists what a Flow may change (`text`, `color`, `hidden`, `icon`, `value`; a Flow value part takes `value` always), and `reset` when it goes back (`never`, `hour`, `midnight` local). The cards' `part` argument lists only parts open to that change, as `Design · Part` (`partLabel()`), id `<designId>/<partId>`; one not open throws. Values are kept in the app setting `customFlowValues` `{[design]: {[part]: {text?, value?, units?, color?, icon?, hidden?, at}}}` (`DebouncedSetting`, 2 s, flushed in `stop()`, the first `onUninit()` group), sent as realtime `custom:flow {design, part, values | null}`, and served in `/state`'s `flow` with `expires`; a timer drops the next to expire and sends `null`. Saving a design drops what its parts no longer allow.
  - Cards: `custom_set_text`, `custom_set_value` (`value` a text arg, a number if it reads as one, optional `units`), `custom_set_color` (Device Values' colour list), `custom_set_custom_color` (`parseCustomColor()`), `custom_set_icon` (Flow Buttons' icon list), `custom_show` (`shown`: show/hide), `custom_reset` (everything Flows set); the condition `custom_is_shown` (hidden by a Flow only: the rules weigh values only the widget has); the triggers `custom_tapped` (a button without a Flow; tokens part, design, dashboard) and `custom_choice` (after a choice was set; tokens choice, value, index). Titles name the widget, *Widget Builder*.
- **The service** (`lib/CustomWidgetService.ts`, `app.custom`): the designs in the app setting `customDesigns` (an array, the library's order; written at once on a save), `save()` (a new one gets an 8-character id; realtime `custom:design {id}`), `remove()`, `duplicate()` (new ids throughout, `<name> (copy)`), `reorder()`, `designItems()` (the widget's Design autocomplete, `custom.partCount`). **`getState(id)`** gathers what a design shows from the services that read it already: `values` by slot (`ValueService.getState()`, so device names, offline, °C/°F as Device Values), `variables` by id, `flows` by id, `histories` by `<span>\n<slot>` (`SparklineService.getState()`), and `flow`; `{missing: true}` for a design that's gone.
  - **A request acts only through its design's own part** (`partFor()`): `setValue()` sets the part's capability (switch: a boolean; slider/stepper: a number clamped to the capability's and the part's range; choice: one of its values, typed to the capability; a temperature shown in °F, and a part range typed in it, converted back to the device's unit), `setVariable()` (through `VariableService.set()`, the personal key), `startFlow()` (`FlowService.trigger()`, the key), `tap()` (a button without a Flow fires the trigger, no key). Routes: `GET /state?design=`, `POST /set` (in `DEVICE_WRITES`), `POST /variable` (`variables` key use), `POST /flow` (`flows`), `POST /tap` (neutral).
- **The widget** (`widgets/custom/public/`, prefix `wb-`, transparent): `createCustomWidget(root, {onSet, onButton, preview, …})`, built once per design (`updatedAt`; a slider's drag survives a refresh) and updated in place. Part classes are `wb-k-<kind>` (not `wb-<kind>`: `.wb-icon`/`.wb-text` are inner elements). Quick Actions' native tile (`wb-tile`, in kit.css's tile lists, so the web backdrop's line and the light-mode shadow apply). A big value at 2 rows (10 fine rows, 40 % free) puts the number at 32 bold with the line under it; a one-column value is icon over value, the name as its tooltip. Taps through the kit's `onTap()`, the slider through `wireBar()`, a stepper's burst sent once 700 ms after the last tap (Variables'), hoped-for values for 10 s, a failure shakes the part with `KEY_PROBLEMS`' text or `custom.setFailed`. A text or number variable is typed in its tile (*Three more*, below). `preview: true` (the builder page) acts on nothing, and shows no *This design has no components yet* (the user, 2026-11-24: it sat over the empty canvas).
- **Mount:** the instance decides web or not; `/state` on load, every 5 min, on `custom:design` for its design and on device names/temperature unit (`onDeviceNames()`); realtime `values:state`, `variables:state`, `custom:flow`; `takeTileShadow()` from its answer, `wireTileShadow()`, `wireHaptic()`.

The preview (`wb-dark`/`wb-light`): a design of drawn tiles, one outlined dashed as in the builder, under the logo's sparkle on the brand colour.

Left: **Parts** (a search, `matchesWords()`, and the groups Show, Control, Layout as the kit's icons; a tap adds the part at the bottom, or into the selected container or the container of the selected part, with a size per kind) and **Layers** (the tree, ↑ ↓ to reorder: later is drawn on top, ⚡ for parts open to Flows). An **overlay** of boxes from each part's rect in the frame: a tap selects, a drag moves, the selected one's corner resizes; the pointer is captured on the overlay (the boxes are redrawn as a part moves). On the top grid and a fine grid a move or resize **pushes overlapped parts down** (`makeRoom()`, from where they were when the drag started, so they come back as it goes on); free-form snaps a part's edges and middle to its siblings' and the box's 0/50/100 % within 2 % with pink lines. Right: **Part** (name or text, the value (`chooseValue()` with `/web/values?type=values`, so every readable capability; a choice on an enum or a yes/no fills its choices), or a variable or Flow from `POST /web/designs/pick`, the range, step, span, choices, a container's mode (switching keeps each part's place, cells ↔ per cent) and background colours (`<input type=color>`), and the place as numbers (columns and rows from 1 for the grids, per cent free-form), Remove), **Look** (colour swatches with *Its own*, the colour names from Dashboard Shortcuts' colour setting so no new strings; icon through `pickIcon()`, pictures not taken; in a container, on a tile or on the background), **Rules** (op, value, colour or Hide, ≤ 6) and **Flow** (a switch per change the kind shows, each with the card it adds; *Back to the design*). Every change draws at once and is saved 500 ms later (`PUT /web/designs`, queued on `wd.saving`); the values are read again 400 ms after a change (`POST /web/designs/preview`, the draft's state without saving). Routes: `PUT /web/designs`, `DELETE /web/designs/:id`, `POST /web/designs/:id/copy` (each answering the library), `POST /web/designs/preview`, `POST /web/designs/pick {what: flow | variable, query}`, all `assertWebSession()`; `/web/setup` has `designs`. - **Building blocks (2026-11-21, the user's pick of five from 16 I brainstormed; the rest, in order: widget state, pages/tabs container, a button's action list, image, ring, repeater (all six built the same day, below), then segmented bar, trend and text input (built the same day, below), and for later: colour picker, embedding an existing widget):**
  - **Sources:** `Source = {slot} | {variable} | {part}` (`sourceOf()`; `part` only a `calc` of the same design and not the part itself, checked after the whole design is read, `checkPartSources()`: a rule naming another is left out, a text's value becomes `null` so `{2}` stays `{2}`'s). A calculated value's own inputs are never parts, so nothing loops. `designSlots()`/`designVariables()` gather every source (own, rules' `of`, texts' `refs`, `inputs`), so `/state` and the builder's preview read them. The widget's `sourceEntry()` reads any of them; the dev mock's `designPreview()` gathers them the same way.
  - **Rules on other values:** a rule's optional `of`. `VALUELESS_KINDS` (shape, text, icon, button, container) keep only rules with an `of`; a clock or date Time has no value either, so the editor gives every rule an `of` there too. **Containers have rules** (hide; a colour tints the background over its own, `!important` over the inline background; solid in Vivid). Editor: per rule *This component / Another value*, then the source picker (Device, Variable, Calculated value).
  - **Shape** (`shape`, Layout): `shape: rect | circle | line` (a circle in a box that isn't square is an ellipse), `background` as a container's (none: its Style colour, else a muted grey), `opacity` 10–100, `radius` 0–32 (rect), `thickness` 1–8 and `dir: horizontal | vertical` (a line; chosen, not guessed from the box, whose shape a free-form container hides). Always `style: none`. Style tab: only the colour. Flow: colour, show/hide.
  - **Calculated value** (`calc`, Display): `inputs` ≤ 12, `op: sum | avg | min | max | diff | count | formula`, `test` (count, the rule ops), `formula` (≤ 120), `decimals` 0–3, `units`, `winner` (min/max: `Name · Kitchen`), `sourceOnly` (left out on a dashboard, `display: none`; faint in the builder, `wb-preview` on the root). **Calculated in the widget** (`calcValue()`) from the values it gets in realtime. Booleans count as 1/0; an unavailable or missing input is left out of sum, average, min, max and count, and makes a difference or formula unknown (`–`). Units are the part's, else the first input's (none for a count). **The formula parser is only the widget's** (`window.customFormula`, the grammar of `parsePriceCosts()` with the names `a` … `l`, `min max abs round floor ceil sqrt`, `,` or `;` between arguments, a point for decimals, `−×÷` read). I didn't make a TS copy as the note had planned: the app never evaluates a formula. The builder asks the preview frame's parser to say *Can't read this formula.* Drawn by the value maker (`wb-k-calc`).
  - **Live text:** `refs` ≤ 6 (`Ref = Source | {time: clock | date | weekday}`, `null` for one that's gone), filled where the text has `{n}` (`fillText()`: `–` for no value, a `{n}` beyond the refs left as typed). *Insert value* appends `{n}` to the text; removing one renumbers the later tokens in the text. A Flow's text replaces the whole text, tokens unfilled.
  - **Time** (`time`, Display): `timeMode: clock | date | since | until`; `seconds` (clock), `dateStyle: short | long | weekday` (date), `slot` (since), `until` `HH:mm` (until; next today or tomorrow). Since and until use `Intl.RelativeTimeFormat` in Homey's language (`8 min. ago`, `in 90 min.`, `now`; minutes up to 2 h, hours up to 48, then days), so no strings of ours. Its rules compare whole minutes. **`updatedAt`:** `ValueService` keeps each value's `lastUpdated` (`lastUpdatedMs()`, read again on every `/state`) and sends it with the slot when known; the widget sets it to now when a realtime value differs. Whether Homey's `lastUpdated` is the last change or the last report isn't checked on the Homey yet.
  - **Ticking and times:** the widget redraws on the minute (on the second with a clock's seconds) while there's a Time or a text with the time, and when the page shows again. `/state` carries `language` and `timeFormat` (riding along, like the tile shadow: no `/time-format` route), and the mount follows `timeformat:state`.
  - Tested in `test/custom-service.test.ts` (reading, sources, `designSlots`), `test/custom-widget.test.ts` (parser, every op, source-only, rules on other values, shapes, refs, times with fake timers) and `test/values-service.test.ts` (`updatedAt`); the builder clicked through in Chromium over DevTools (a calculated value's form and a bad formula, Time, a shape's rules and Style, inserting a value, a container's Rules tab, adding the three new kinds; no errors). Look: `blocks` (*Text with values, sums, the time and shapes*; the mock's scene `blocks`, *At a glance*). 58 new strings, all 13 languages.
