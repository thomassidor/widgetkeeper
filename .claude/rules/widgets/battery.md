# Batteries widget (`battery`, 1.4.1)

- **Origin**: Drako74's forum ask (#451, 2026-11-26; Feedback Desk wk-137): many battery-powered devices on a status dashboard, showing only their battery levels, without a Device Values tile and colour Flows for each; in #454 he suggested a separate widget with green/yellow/red levels. The user's choices (2026-11-27): **a widget of its own, not a Value Board option, and not built on Value Board** (the user: "This is a new widget. Don't worry too much about how value board is made"). Five directions mocked up (`temp/battery-widget-directions.html`: list, bars, at a glance, grid, buckets): the grid. Then six cell layouts (`temp/battery-cell-variants.html`; the number right after the icon looked odd): **the level top left, a battery top right, the name under both**. Turned down: a Value Board `values: battery` option, "none picked = every battery device" (Combined Value's `devicesOptional`), a summary ring, bars, buckets. Name **Batteries**; transparent; in Add widget's Values group; not a Smart Stack page (tall, like Value Board); on the web dashboards through `WEB_APIS`.
- `lib/BatteryService.ts` (`app.battery`), on `DeviceTracker`: per device the first `measure_battery` and the first `alarm_battery` (a sub-capability too, sent by its base id), re-tracked when those change. `GET /state?deviceIds=` → `{id, name, level, low}` (each null when the device hasn't it or hasn't reported; `...offlineFlag()`), `{id, name, none: true}` for a device with neither (left out by the widget), `{id, missing: true}`. Realtime `battery:state {deviceId, capabilityId: 'measure_battery'|'alarm_battery', value}`. Names through `deviceNamer()`. No temperatures (`test/temperature-unit.test.ts` lists it).
- Front end (`widget.js`, `bt-*`): one tile, the heading `Batteries` (14 medium) and `N low · M fine` (`· K unavailable` for unavailable and missing ones; an unavailable device is never fine) muted on the right; a grid of cells with Room Health's hairlines, 2/3/4 per row (`columns`, default 3: names fit at 358 px), **lowest first** (`batteryOrder()`: a low alarm on before every level, OK after the levels, one that hasn't reported after those, a missing device last as `–` / `Unavailable`; ties keep the picked order). A cell: the level (17 bold, a small `%` after it; `Low`/`OK` for an alarm-only device), a 22×13 battery glyph drawn as SVG filled to the level (Low nearly empty, OK full), the name under them (12/16 muted). A realtime change sorts again (the whole tile is drawn).
- Levels (`batteryLevel()`): below `redBelow` (10) `alert`, below `yellowBelow` (20) `warn`, else `fine`; a low alarm on `alert`, off `fine`; the level wins over the alarm. Settings typed as text or out of range fall back or clamp to 0–100. `greenWhenFine` is **on by default** here (the mock-ups were green; Value Board's is off). Muted: low cells washed (14/16 %), the number and glyph in the level's text colour, fine ones green text without a wash; Vivid: solid shades with `--wk-on-*`, as Value Board.
- Rename tiles (`.claude/rules/tile-names.md`): keys by device id; a field per device in place of the grid (a missing one has none).
- Unavailable: dimmed, the kit's mark bottom right (the top right holds the battery).
- `dev/battery-preview.html`; Looks in `dev/variants-list.js`; `npm run test-dashboards -- battery`. Not yet seen on the Homey or in the phone apps.
