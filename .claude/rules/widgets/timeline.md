# Chart · Timeline widget (`timeline`)

- When was it on, open or moving? A row per logged boolean (up to eight) over the time span: its name (12/16) above a 10 px track (the text colour at 7 %), bands where it was true in the row's colour, at least 2.5 px wide (a door opened for seconds), the hours to come dimmed (`.future`) behind a dashed line at now. The axis runs the widget's whole width (the chart kit's `timeLabels()`, drawn in a `<g>` moved back by its `L` gutter); no value scale. One of the two chart types mocked up with 1.2.0's four and kept for later (`docs/specs/chart-timeline-and-stacked.md`), built at the user's ask (2026-10-29). Not transparent: `homey-widget`. On the chart frame and mount helper (Charts' note); its height follows its rows (32 px each).
- **Data: the Heatmap's recording**, not Insights (a boolean's log is only its last 50 changes, CLAUDE.md *Insights*). `GET /state?slots=<deviceId:capabilityId>,…&from=<ms>` → `{rows, language}` (`lib/timelineState.ts`): Device Values' state per slot (`values.getState()`, so the name, capability and live `values:state` come with it) with `HeatmapService.getChanges(deviceId, capabilityId, from)`: the recorded changes from `from` on, led by the last one before it (the state the window starts in), and `since`, the first change known. It starts and shares the Heatmap's recording (`recording()`: the backfill, the subscription, the file, the 8-day forgetting), so a value shown in both is recorded once. A row whose changes can't be read is drawn unknown; a value that isn't a logged boolean throws there. Before `since` a row is a dashed line (`.tl-unknown`), never guessed; with no change known at all, the header says `noHistory`.
- What true means (`kindOf()`, exported as `createTimelineWidget.kindOf`): `alarm_contact`/`alarm_door`/`alarm_window` open, `alarm_motion`/`alarm_presence`/`alarm_occupancy` motion, other `alarm_*` active, anything else on; each kind has its words (`timeOn`/`countOn`, `timeOpen`/`countOpen` …; flat keys, as the 'fallback strings' test reads them). Booleans only (the user's choice, 2026-10-29: numbers over a threshold could come later).
- Settings (22, from `scripts/chart-settings.json`): `slot1`…`slot8` ("Value 1" …, Chart · Ranking's setting; Sparklines' `listSlots(query, 'boolean')`, `booleanCaps()`: logged booleans), each with its `colorN` (the user's choice of a colour per row; defaults the kit's `COLORS` in order, blue, red, orange, yellow, green, purple, then blue and red; a missing one takes that order too), so each value is a group in the web editor; the time span block (default today, `1d!`; its hint says the recording keeps about two weeks), `title` (a chip above the rows; none without), `showHeader`, `colorStyle` (Muted: bands mixed 70 % into the card; Vivid: full colour).
- Header: the first row's time on over the span (`5:40 h`, under an hour `25 min`, `<1 min` for seconds; `On · Heating`) in its colour, and how often the second (or the only) row turned true (`8`, `Detections · Hall motion`). A tapped row: its own time on and count. A tapped band (within 4 px): its length, with its times under it (`16:05–17:30`, with weekdays over several days; as the sub line, as 24 px bold didn't fit the 300 px widget) and the row's count. Kept as the row's place and the band's start.
- Live: `values:state` adds a change to every row with that value (a value equal to the last is ignored; it sets `since` if there was none); redrawn every minute; refetched every 5 min, keeping live changes newer than the refetched ones.
- `dev/timeline-preview.html` (`mock-timeline.js`: the showcase house's heating, hall motion, front door and TV, each day alike, on the minute), the preview frames `tln-dark`/`tln-light` (the prefix `tl` is Notes'), the README screenshot `timeline` (the mock-up's orange, yellow, red and blue). `npm run test-dashboards -- timeline` (under Test charts). The previews and screenshots were rendered with Playwright's Chromium in a cloud session (Edge isn't there), matching the Edge renders' size and font. Not yet tried on the Homey or the phones.
