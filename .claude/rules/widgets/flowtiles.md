# Flow Tiles widget (`flowtiles`)

- Device Values' tiles whose content comes from Flow cards, not devices (the user's idea, 2026-11-04: "like Device Values but configured mostly through Flows, other than basic design settings"; the plan and its two rounds of answers in that session). The name Flow Tiles was the user's pick over Status Tiles and others. 1.3.0. `lib/FlowTileService.ts` (`app.flowTiles`); transparent.
- **Device Values' tile, not a copy:** `index.html` loads `../values/widget.css` (and `../values/widget.js`, as a `DEPS` entry is both files: `values/widget` in the Smart Stack's `DEPS` and the tests' `DEPS`) before its own `widget.css`, and the root is `vt ft`, so every `.vt-*` rule (compact and pill tiles, the 22 % tint, Vivid's shades and `.vt-ink` copy, the fill gradient, the shake) applies as it is. `widget.css` only adds: 1 column, no icon (`.ft-none`: an empty mask would show as a square; the second line never has one; a compact text without an icon starts at the left), a fill without a colour in blue, the tappable tile, and the tap's highlight. Its tiles are built by Device Values' code (`window.valueTileParts()`, which is why the `widget.js` is needed; `test/widget-html.test.ts` checks there's no copy). So a change to Device Values' CSS changes Flow Tiles: look at both screenshots. Device Values' own code wasn't touched (its screenshot stayed byte-identical).
- **Boards**, because a Flow can't address a widget instance (as Notes' notes and Days Since's counters): a tile is on a named board, and every Flow Tiles widget showing that board shows it. `flowTileKey()` (trimmed, lower-cased, ≤ 60, `__proto__` & co. refused; the widget's copy `window.flowTileKey` is checked equal) keys both boards and tiles; the default board is `Tiles` (English in every language, like Notes' `Note`). The app setting `flowTiles` `{[board]: {name, updatedAt, tiles: {[tile]: {name, kind, text, number, units, decimals, second, icon, color, fill, order, updatedAt}}}}`: at most 20 boards and 24 tiles a board (those a Flow wrote longest ago go, a write of the same value counting; after a restart by `updatedAt`), texts cut at 60 (whitespace folded), units at 12. Kept in memory and written 2 s after a change (`DebouncedSetting`; a Flow on a meter may set a tile every 10 s), flushed in `stop()` (the first `onUninit()` group). A change that changes nothing isn't saved or sent. A saved setting is read leniently (`readBoards()`): what's not well-formed is left out.
- Realtime `flowtiles:state {key, name, tiles}`: a board's whole entry, the changes of 250 ms gathered (a Flow setting five tiles is one event per board); a cleared or dropped board is sent with no tiles (its key as its name). The widget takes the event whose `key` is its board's.
- **Flow cards** (`app.ts` `registerFlowTileFlows()`), each changing only its own part, so one Flow can set the value every minute and another the colour: `flowtiles_set_text` (`text`), `flowtiles_set_number` (`number`, `units` an optional text, `decimals` `auto`/`0`/`1`/`2`), `flowtiles_set_second` (optional `text`: empty removes it), `flowtiles_set_look` (`icon`: Flow Buttons' `listIcons(…, {none: true})`, with their PNG previews; `color`: Device Values' card's list, `default` and `TILE_COLORS`), `flowtiles_set_fill` (`percent` 0–100, clamped), `flowtiles_remove_fill`, `flowtiles_remove`, `flowtiles_clear` (the board). The first five make the tile if it isn't there; a tile goes at the end of its board, and takes the name as the latest card spells it. `board` lists `listBoards(q, {create: true})` (Tiles, the boards with their tile count, then what's typed as *New board*), `tile` `listTiles(q, args.board, {create: true})` (that board's tiles, then *New tile*). An action given *Any* throws (`argName()`).
- The fill and its colour are the Flow's, not settings (the user, after the plan had Device Values' `percentFill`/`redBelow`/`yellowBelow`: "should be a flow thing"): a fill is its own value (a tile can show 214 km filled to 82 %), in the tile's colour, blue without one; a Flow wanting red below 10 % sets the colour itself.
- **Taps** (the user's ask for version 1): the trigger `flowtiles_tapped` "Flow Tile [[tile]] on [[board]] was tapped" (both args offer *Any*, `ANY_ID` `flowtiles:any`; tokens `board`, `tile`, `value`: the text, or the number as `FlowTileService.valueText()` gives it, up to 2 decimals or the card's, `°`/`%` attached). Only tiles a Flow listens to are tappable: the app reads the trigger's `getArgumentValues()` at start and on the card's `update` (a Flow using it saved), keeps `<board>\n<tile>` pairs (`*` for Any) in `setListeners()`, and a change sends every board again; each tile in `/state` has `tappable`. A tap is `POST /tap {board, tile}` → `tap()` fires the trigger with state `{board, tile}` keys, matched by `matches()`; a tile that's gone throws (the widget shakes it, `flowtiles.tapFailed`). No API key: the app fires its own card (`NEUTRAL` in the web dashboards' test). The kit's `onTap()`; `Homey.hapticFeedback()` in a `try`; taps while one is on its way are ignored; a tappable tile is `role="button"`, `tabindex="0"`, `cursor: pointer`, scales to .97 while pressed.
- Settings (8): `board` (autocomplete, `listBoards(q, {create: true})`; none picked is Tiles), `only` ("Show only": tile names separated by commas, shown in that order, repeats and unknown ones skipped; a name with a comma can't be listed; the user picked it over tile autocompletes), `order` (`added` default, `name`: `localeCompare` in Homey's language; ignored with Show only), `columns` (`3`/`2`/`1`), `tileStyle`, `colorStyle`, `tapEffect` ("On tap": `highlight`, the default: an inset shadow over the background but under the text, the tile's colour or blue, in Vivid on a coloured or filled tile the ink, 45 % fading out over 0.6 s; or `none`; the user asked for the option), `showAge` ("Show when it changed", off: the kit's `formatSince()` of `updatedAt` where no second line is set, drawn again each minute, Homey's `now` correcting the screen's clock).
- `GET /state?board=` → `{now, language, board: {key, name, tiles}}`. The kit's `wireRefresh()`: every 5 min, when the page is back after 30 s hidden, and 5, 15 and 30 s after a failed read; only the latest read's answer counts, and a board event during a read reads again, so a read that left before the change can't undo it. A failed refresh keeps the tiles with a transient message, only a failed first load says `flowtiles.error`. Empty: `flowtiles.empty` ("No tiles yet. Add one with the Flow card Set Flow Tile."), or with Show only and a board that has tiles, `flowtiles.noneShown`.
