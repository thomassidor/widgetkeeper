# Notes widget (id `textline`)

- A short message (wk-044: a user asked for a text line; the user's brief: a normal tile, or a realistic Post-it stuck on the dashboard in handwriting; then the name Notes and a message typed in the settings). Transparent. `lib/TextLineService.ts` keeps the Flows' texts. The id, Flow card ids, app setting and events keep `textline`; only what users read says Notes / note.
- `source` (`Text from`): `typed` (default), `flow` or `variable`. `message` (a textarea) is the typed note; with `flow` or `variable` it shows while they have no text (else a muted `No message`). Typed and empty: `Type your note in the widget settings.` A typed note makes no requests.
- Named notes ("boards" in the code; names, because a Flow can't address a widget instance): `board` (`Note name`, default `Note`), keyed by `boardKey()` (trimmed, lower-cased; `window.textLineBoardKey`). The app setting `textLines` `{[key]: {name, text, color, updatedAt}}`: at most 50 (the oldest go), text cut at 500, a cleared note deleted. Realtime `textline:state {key, name, text, color, updatedAt}`.
- Flow cards (`.homeycompose/flow/actions/textline_*.json`; `app.ts` `registerTextLineFlows()`): `textline_set` "Write [[text]] on the note [[board]]" (resets the colour), `textline_set_color` "… in [[color]]" (the user asked; `TILE_COLORS`; 1.2.0's six have Post-it papers of their own), `textline_clear` "Clear the note [[board]]". `board` autocompletes `listBoards()` (`Note`, the notes with a text, then what's typed as a new note; the id is the name). A Flow's colour wins over the widget's own. **Custom colour** (1.4.0, a forum request, 2026-11-20; the user's picks: new cards beside the old ones, as a card can't switch its fields and a changed card breaks Flows; tinted 22 % in Muted like the named ones; hex and rgb only, no names): `textline_set_custom_color` with a `color` text arg (tags work); `parseCustomColor()` (`lib/tileColors.ts`) makes `#F00`, `FF0000` or `rgb(255, 0, 0)` a lower-case `#rrggbb` (empty → `default`, anything else throws *Unknown colour*), stored and sent like a name. The widget draws it with the kit's `paintColor()`: `data-color="custom"` with `--wk-custom`, `--wk-on-custom` (white or `#1A1B21`, whichever contrasts more) and `--wk-on-custom-muted` inline (the text as `textline_set_color`): the tile's tint, Vivid's text, and a Post-it paper of it mixed into white (45 %, top 30 %, bottom 55 %), so the blue-black ink stays readable. Not yet run from a Flow on the real Homey.
- `variable` autocompletes `listVariables(query, {types: ['string']})`, read through Variables' `getState()` with the app's token (its tracking and `variables:state`).
- `GET /state?board=|variable=` → `{language, board, variable}`. Flow and variable notes refetch every 5 min and when the page becomes visible. Diagnostics' `textLines`: counts only, never texts.
- Tile (`style: tile`): Variables' row with an optional 20 px icon (`icon`, `listIcons(…, {none: true})`; the kit's `icons`) and one line (a typed line break becomes a space). `size`: small 14/20 regular, default 17/24 medium, large 24/32 bold. `align`. `overflow`: `ellipsis`, `scroll` (only when it doesn't fit: to the end and back at 40 px/s with 15 % pauses and 8 px soft edges; off with reduced motion) or `wrap` ("Show on more lines"; a user asked, 2026-10-24, for a text that stays up: every line, no cap, the typed line breaks kept with `pre-line`, the tile growing through `setHeight`; `data-overflow="wrap"` on the root. Its padding puts one line where the centred 48 px tile has it, and the icon sits by the first line). `color`: Device Values' 22 % tint.
- Post-it (`style: postit`): `.tl-note` holds the tilt (2–3.5° either way from the instance id, `textLineTilt()`; the user asked for more than the first 0.6–1.8°) and the paper's shadow as a `drop-shadow` filter, so it follows the cut corner. `.tl-paper` is cut diagonally at the bottom right by a `mask-image` (`--tl-fold`), and its `::after` is the folded ear (the user's request). No line across the top (the user disliked the glue strip). Yellow by default, or the colour's paper (red → pink, purple → lavender …); blue-black ink in both modes. Up to 3 lines of handwriting (`-webkit-line-clamp`, `white-space: pre-line`): `fitNote()` steps the size down until it fits, measured with the clamp lifted and by `offsetHeight` (the tilted note's `getBoundingClientRect()` is ~10 px taller, which shrank every three-line note). No icon.
- Font: **Caveat** (SIL OFL, `widgets/textline/public/fonts/` with `OFL.txt`; Latin, Latin Extended and Cyrillic, weight 500, from `@fontsource/caveat` 5.2.6) as `Widgetkeeper Caveat`; Korean and Arabic fall back to the system font. **Fonts are local only** (the user: no Google Fonts). `mount.js` asks `document.fonts.load()` before `ready` (≤ 1 s); the note refits once fonts are in.
- Not yet tried in the phone apps: font loading in their WebViews, and the Android text zoom against the note's px sizes.
- **Markdown** (`markdown`, *Format with Markdown*, 1.4.1; a forum user using Notes for greetings asked for text formatting, 2026-11-28; the user's picks: a setting, inline styles plus headings and lists, Caveat Bold for the Post-it): a checkbox after `variable`, `value: true` so a widget placed from now on has it, but the mount reads only `=== true`, so one placed before (no stored value) stays plain: its Flow or variable text may hold `*` or `_` meant as they are. `parseMarkdown()`/`parseInline()` in widget.js (`window.textLineMarkdown`), drawn as nodes (`el()`, text nodes), never `innerHTML`: `**`/`__` bold, `*`/`_` italic (`_` only at a word's edge, so `snake_case` stays), `~~` struck, `` ` `` code, `\` escapes; per line `#`–`###` (deeper is `###`), `-`/`*`/`+` and `1.`/`1)` lists (two spaces a level, up to 3), `>` quotes. No links, tables or images (not picked). Only the note's text is formatted, never the widget's own muted messages. Show on more lines: a `div.tl-line` each (headings 1.5/1.25/1.1 em, hanging-indent lists, a quote's bar; an empty line a zero-width space, as `pre-line` kept it). One line and the Post-it: spans in the text's flow with `\n` between them (the one-line tile's `nowrap` makes them spaces, the Post-it's `pre-line` keeps three); headings only bold there, as bigger ones made `fitNote()` shrink the note. **Caveat Bold** (`fonts/caveat-*-bold.woff2`, 700, the same `@fontsource/caveat` 5.2.6) for the Post-it's bold; the mount asks it before `ready` when the setting is on. Italic on the Post-it is the browser's slanted Caveat (it has no italic). The large tile's bold is 900 (its text is already 700). `dev/textline-preview.html` w16–w19; Looks `textline-markdown`.
- Colour style (`colorStyle`, Muted/Vivid; CLAUDE.md *Widget styling*, `kit.css`): after `color`. `--tl-<colour>` are the palette's. Vivid: a coloured tile is the shade at full strength with white text (dark on yellow); the Post-it keeps its paper.
