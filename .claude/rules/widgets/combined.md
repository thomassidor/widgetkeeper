# Combined Value widget (`combined`)

- One full-width tile: one number capability read from several devices, folded into one value. The user's pick of two rounds of mock-ups (2026-11-04; `temp/aggregate-mockup.html`, then `temp/aggregate-mockup-2.html` with the decisions): Device Values' compact tile, full width, with the value large on the right and the range under the name (no device count); the dots and the share bar of the first round, generalized, on by default; the pill is Device Values' pill with the dots on the right; the range optional everywhere. The name "Combined Value" and the id were picked when building it (the user didn't object to the working name). Display only, no taps; transparent.
- Settings: `capability` (autocomplete, Value Matrix's `listColumns()`: every number capability on the Homey by id, `units · N devices`, `None` first), `show` (`avg` default, `sum`, `min`, `max`, `range` "Lowest – highest"), `name` (text; empty: the capability's title from the first counted device), `range` (on), `chart` (on), `tileStyle` (Device Values' `compact`/`pill`, its hint), `color` (`default`, a plain tile, then the palette; not in `PICKERS`, whose colour defaults to blue), `colorStyle`. The `devices` setting has no filter. An autocomplete doesn't get the devices, so the value is picked across the Homey and the devices narrow it.
- `lib/CombinedService.ts` only picks the devices: the picked ones that have the capability (`matrixCaps()`), in order, a repeat once (a deleted one is `{id, missing: true}`, logged; one without the value isn't counted at all); with none picked, every device with it, by name (`devicesAndZones()`, its shared 5 s read). The readings are Value Matrix's cells (`ValueMatrixService.getState(ids, [capabilityId])`): its tracking, device names (`shownName()`) and realtime `valuematrix:state`, which the mount filters by the counted ids and the capability. No service of its own to stop.
- `GET /state?capabilityId=&deviceIds=` (`deviceIds` optional) → `{capability: {id, title, units, decimals, min, max} | null, devices: [{id, name, value: number | null} | {id, missing: true}]}`; `capability` null when no counted device has it (the widget says `noDevices`). Without a capability (or `None`) the mount says `selectValue` and asks nothing. Refetched every 5 min (also picks up a new device when none were picked) and on a device names change.
- Folding (`combineValues()`, on `window`): the readings that are finite numbers; a missing device or a null reading is left out and the line says `N of M not read` in place of the range (a dash for the value when none answered). Average and sum as Homey reports (a 0–1 `%` is scaled in `formatNumber()`); the average with `averaged` (three significant digits within the decimals). Numbers in the device locale, `−` for minus; units tight for `°…`/`%`, else spaced; on the tile the units are a 20 medium span after the 32 bold number (`.cv-number`, `.cv-units`).
- The line under the name: Lowest/Highest put the device first (without the chart the only place it shows), then the range when on (`19.6–23.1°C`; spaced ` – ` when a number is negative); Lowest – highest is the value itself, so no line and the name centred (`.cv-head.one`). The pill puts the value first on that line (`21.8°C · 19.6–23.1°C`) and hides `.cv-value`. The mock-ups' known repeat: Lowest/Highest with the range shows the value again as the range's end (the user was told, 2026-11-04).
- The chart (`data-chart` on the root: `dots`, `share`, `none`): a sum of values all zero or more (and above zero in total) gets the share bar, everything else the dots.
  - Dots: one per device on a shared scale (`scaleOf()`: 0–100 for `%`, so a low battery sits left; else the lowest to the highest with 8 % room, kept from going below zero when every value is above it), the band lowest to highest (30 % accent, 45 % in Vivid), a zero mark where the scale crosses it, the average a 3 px accent tick (Average only). Lowest/Highest highlight that device's dot, Lowest – highest both ends and the band. Under the strip the lowest and highest devices' names (the one the value comes from in the text colour, 500); one device, one name. Each dot's `title` is `name: value`.
  - Share: every device with four or fewer, else the biggest three and Others; kit.css's bright blue, green, orange, purple and the dots' grey for Others, mixed 85 % into the tile in Muted, full in Vivid; the legend names each with its rounded %. The pill has no legend and no end names.
- Look: Device Values' tile (`#181920` dark with the rim, 10 px radius, 8/10 padding), the head 40 px (the value's line), the icon the kit's `valueGlyph()` (moved there from Device Values; the capability's own icon isn't read, as Value Matrix's cells don't carry it). The pill: Sensor Alarms' 52 px, `#2B2C36` dark, the 24 px muted icon, 14/18 lines, the chart 96 px on the right. Track and dot colours are mixed from the text colour into the tile's own background (`--cv-bg`), so they work on a tinted or a Vivid tile.
- Colours: tinted (CLAUDE.md *Widget styling*). A colour mixes `--wk-c` 22 % into the tile (Muted) and makes the accent its bright set; Vivid fills the tile with the shade and draws text, dots and share in `--wk-on` (the share's parts by strength). Vivid without a colour only strengthens the share and the band.
- `dev/combined-preview.html` (`?mode=light`, `?w=300`: twelve cases, each tile then pill). README screenshot `combined` (three widgets stacked: the rooms' average, the big users' power, the lowest battery as a pill; made up in `dev/mock-dashboard.js`). Preview frames `cv-dark`/`cv-light`. `npm run test-dashboards -- combined`. A Smart Stack page type. Not yet seen on the Homey or in the phone apps.
