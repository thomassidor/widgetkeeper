# Chart · Lines widget (`lines`)

- Up to six values over time on one chart, a line each in its own colour: every room's temperature, each radiator's power. The user's pick (2026-10-30) of the gaps left after 1.2.0's chart widgets, as its own widget rather than more series in Chart · History (whose 26 settings, ten per series, would have grown by ~40: the rule in Totals' note). Charts' one-chart plot (122 px) with a left value scale, and a right one for a second kind of value. Not transparent: `homey-widget`. On the chart frame and mount helper (Charts' note); built from Chart · Stacked's code (the legend, units, colours, keep-live-points), drawing lines where Stacked stacks.
- Data: each value's window through `/state` (`lib/chartState.ts`, Sparklines' `getWindows()`, up to 120 points each), drawn as they come (no common grid: each line its own points), the value now carrying a line on to now while the window is live. No live points on a 6-hourly span (the kit's `sixHourSpan()`), as Charts.
- Units and sides (`plan()`): the first readable value sets the left side's units, the first that can't go on it the right side's (the user's ask, 2026-10-30, so Lines owns "several values" and History is left with one value and its comparisons); W/kW/MW and Wh/kWh/MWh are scaled onto a side's units (`UNIT_SCALE`, Stacked's), a 0–1 `%` by the kit's `scaled()`; a value in a third kind of units is left out, its chip muted with `Other units`. Only when lines on both sides are drawn: `kit.dualScale()` (Charts' two on one chart, `fit` unless `range: zero`) and the plot `R` (34 px) narrower; else one `valueScale()`. Each side's units once: with one side on the title chip (else the first drawn line's chip), with two on each side's first drawn line's chip. The header writes a value to its side's first value's decimals and units; a tap's nearest line is measured on each line's own scale (`drawn.yOf(l)`).
- Scale: `range` (Charts' `fit` default: `valueScale({fit: true})` over every drawn point; `zero`: from zero, below it where a value goes there). `smooth` (Charts' `smoothValues()` and the monotone path; the header keeps the real values).
- Settings (22, from `scripts/chart-settings.json`): `slot1`…`slot6` (Chart · Ranking's "Value N", hint `lines.slot1`; Sparklines' `listSlots(query)`, logged numbers) each with its `colorN` (the kit's `COLORS` in order by default, as Timeline's and Stacked's), the time span block (default 24 hours), `style` (`lines.style`: `line` "Lines" default, `area` "Lines with areas", each area 12 % of its colour, closing at the scale's `baseY`), `range`, `smooth`, `legend` (Charts'), `title` (a chip first in the legend), `showHeader` (hint `showHeader.lines`), `colorStyle` (hint `colorStyle.lines`; Vivid: 2 px lines, areas at 24 %).
- The legend: Stacked's, a chip per value in the page's flow, wrapping, above the plot or with `legend: below` under its labels; the plot always starts `TOP_PAD` (10 px) into the svg.
- Header: the first two drawn values now (`21.5 °C`, `Kitchen · Now`, each in its colour), or over a finished span their averages (`Kitchen · avg`, `lines.average`; each point weighed by the time to the next). A tap: the line nearest the pointer's height at the nearest point's time, then the next nearest (`Office · 03:00`; a weekday before the time over more than a day, the date over more than 8 days), a cursor line and a dot on every line there. Kept as the time (and the pointer's height), so it stays put as the window moves. Without a tap and while live, a dot (`kit.dot()`, kind `ln-dot`: not `ln`, which is the root's class and would reset the colour variable) on each line's latest point.
- Live: `values:state` onto every line with that value (not on 6-hourly spans); redrawn every minute; refetched every 5 min, keeping live points newer than the refetched ones.
- `dev/lines-preview.html` (`mock-lines.js`: the showcase house's living room, kitchen, office and bedroom, each its own day, a point every 12 minutes on the clock's marks, to 2 decimals as averages are), the preview frames `lns-dark`/`lns-light` (four lines: blue, orange, green, purple), the README screenshot `lines` (24 hours, the four rooms). `npm run test-dashboards -- lines` (under Test charts). Previews and the screenshot rendered with Playwright's Chromium (headless Chromium hung on `--screenshot` as root; a Playwright render of Timeline's preview and screenshot matched the committed ones byte for byte). Not yet tried on the Homey or the phones.
