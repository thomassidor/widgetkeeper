# Renders (app images, previews, screenshots, clips, showcases)

- Renders run headless Edge through `scripts/headless.mjs` (`EDGE`, `HEADLESS`, `freshProfile()`, `edge(args, {virtualTime})`: default `--virtual-time-budget=4000`, `null` for none; `withServer(fn)`: the repo root served on 127.0.0.1 by a child process (the file run with `--serve`, since `edge()` blocks), for the pages that fetch files or show a page in the Web Page widget, which wants http(s): screenshots, showcase, web-showcase and whats-next; the icon download, which keeps an earlier `temp/screenshot-icons.js` or writes one without icons where my.homey.app can't be reached). In a cloud session (no Edge, my.homey.app blocked): `EDGE` a wrapper that runs Playwright's `chrome-headless-shell` (`/opt/pw-browsers/chromium_headless_shell-*/…`) with `--no-sandbox` and drops `--headless=new` (the full Chromium there never exits headless, even on a `data:` page), and Roboto installed locally (`~/.fonts`, from Google Fonts' TTFs), as the browser can't fetch the Google Fonts stylesheet; such renders lose the library icons and differ in antialiasing from Edge's (2026-10-31). They show made-up data on a fixed clock: **never put real device names or readings in them.** Every render is byte-identical between runs, except the live electricity chart's antialiasing (the electricity screenshot and the Home, Energy and Kitchen showcases). An endless CSS animation isn't (its phase varies): `screenshots.html` and `showcase.html` hold the Keypad's pulsing dot still (`.kp-dot.next`); do the same for a new one.
- On the NAS build box (2026-11-03; what else differs from the PC is in CLAUDE.md's *Build box or PC*): `EDGE=/work/buildbox/chromium-render`, the buildbox repo's wrapper around Playwright's headless shell, as in a cloud session (the box runs as root, so `--no-sandbox`), with Roboto from Debian's `fonts-roboto` (the buildbox repo's README, *Extras*); the library icons are there. The box runs on UTC, and the made-up data follows the fixed clock's local time, so its first renders had other readings (Chart · Scatter's 6.5 °C for 6.8): `headless.mjs` sets `TZ=Europe/Copenhagen` for the browsers everywhere but Windows. Linux draws text differently from Windows, so its renders differ in antialiasing from Edge's (the same data, under 2.5 % of pixels changed much): the committed images come from both the box and the PC (the user, 2026-11-04), so one re-rendered on the other machine changes nearly every pixel's antialiasing: render and commit only the images a change is for, and compare byte for byte only against one made on the same machine. It's slow: previews ~9 min, screenshots ~11, the first clips ~4 min each. Every script prints `[n/total] wrote <file> · ~N min left` (the last `· done in …`; `scripts/progress.mjs`, tested in `test/render-progress.test.ts`; the user's ask, 2026-11-03), so a run can be followed. The clips' browser is killed and its profile removed only once it has exited: 500 ms after the kill it was still writing there on the box (`ENOTEMPTY`), which stopped the run.

One run per image, ~20 s each on the box. `test/widget-looks.test.ts` checks every page has a light image and another, Vivid where the widget has the Colour style setting, and no image is missing or left over; each widget's images that do more than change colours (at least 4, `FEW_MODES` for those with less to show), an image for each setting that changes its look (`SHOWN_SETTINGS`: a new setting goes there and in the list), the offline Look (`SHOWS_OFFLINE`) and labels that fit the image's line (50 characters).   - A clip is steps in `CLIPS`: `say` (with `icon`), `wait`, `tap`/`drag` (a selector, the match's index `i`, points as fractions of its box), `type` (`Input.insertText` a key at a time, then Enter), `run` (a control on `window.clip`, e.g. `doorbell`), `probe` (prints a page value).   - Rendered at 1x (touch moves 1:1), screenshots at 2x (`clip.scale`). Headless Edge scrolls a native scroller only half as far as dispatched touch moves (2026-10-10), so the stack's swipe runs on past the edge; `Input.synthesizeScrollGesture` didn't scroll at all.
